# Diego Guevara — portfolio

A local-first portfolio for IS218 and future opportunities. It uses static HTML and CSS generated by a small Node.js script: no framework, database, API keys, analytics, or runtime JavaScript. Content is stored separately so you can update it without redesigning the page. The build copies only the generated page, stylesheet, and `public/` assets into `dist/`.

## Run it

Install Node.js 20 or newer and npm, then from this folder:

```sh
npm install
npm run dev
```

Open the local address printed in the terminal. The development command builds once; after editing files, stop it with Ctrl+C and run it again. To generate the deployable site without starting a server:

```sh
npm run build
```

Open `dist/index.html` or serve `dist/` with a static server. `npm run preview:alternative` generates the notebook-style comparison in ignored `.preview/` and serves it locally. Stop the server with Ctrl+C. Set `PORT=4174` before a command if the default port is occupied. There are no lint, type-check, or automated test scripts configured; see the project record for checks actually performed.

## Update content

- `src/content/site.json`: introduction, interests, skills, experience, profile URLs, contact email, and résumé path. Empty links are hidden. Add confirmed experience entries to the `experience` array using `title`, `organization`, optional `dates`, and `summary`.
- `src/content/projects.json`: featured order (array order), project labels, status, tags, case-study sections, and links. Add or remove sections as evidence becomes available. Keep `id` unique, short, and URL-safe; `number` is a display label. Use real links and describe your own contribution accurately.
- `scripts/build.mjs`: page structure and a small number of section headings and explanatory sentences. The group-project placeholder is here until the actual course project is confirmed.
- `src/style.css`: colors and fonts are CSS variables near the top; layout and responsive rules follow.
- `docs/PORTFOLIO_RECORD.md`: concise public course record and review follow-up.

JSON needs double quotes, commas between entries, and no trailing comma. For example, this is **sample data only**, not a claim about Diego:

```json
{"title":"Example role","organization":"Example organization","dates":"2025–2026","summary":"Replace with a verified contribution."}
```

To add a project, copy an existing object in `projects.json`, change its unique `id`, `number`, text, sections, tags, and verified links. Remove unverified sections and links; an empty `links` array is fine. Rebuild and check the card and case study. For a group case, explain what you did, what teammates did, and what remains planned. Replace the group placeholder in `scripts/build.mjs` when the required customer project is known.

## Résumé, contact, and images

The public résumé is `public/Diego_Guevara_Resume.pdf` and its editable source is `docs/resume.html`. To revise it, edit the HTML, open it in a browser, and use Print → Save as PDF with letter paper and background graphics enabled. Replace the PDF in `public/`, then rebuild and verify the link. The path is set by `resume` in `site.json`. The original supplied PDF remains in the project root. Set `email` to an address you want public, and `linkedin` to your actual profile URL; empty fields produce no link. GitHub URLs are derived from the local Git remotes; confirm you want them public. A GitHub profile is not necessarily a direct contact method, so add an email or other verified contact route before sharing widely.

Add a real project screenshot to `public/` and add an image object to the relevant project, for example **using your own actual filename and description**:

```json
"image": {"src":"./assets/example-screen.png", "alt":"Description of what the screenshot shows", "caption":"Optional context"}
```

Use descriptive alt text for meaningful images, never invent a screenshot, and only include files you have permission to publish. Do not put private documents in `public/`.

## Course record and privacy

Update the public record with actual evidence, changed/checked/next notes, and a real peer review and retest when they happen. The example rubric in the brief is a quality guide; consult Canvas for official requirements and deadlines. RPS-001 is a separate assignment.

`private/README.md` is a tracked blank template. Copy it to `private/career-research.md` for role cards, comparisons, and personal reflections. Files under `private/` other than the template are ignored by Git and excluded from the build. The temporary project copies under `docs/Tempo-AI-Assistant/` and `docs/alpfa-njit-app/` are also ignored and excluded from the build; the portfolio does not depend on them. This is a safeguard, not encryption: check `git status` and `git diff --cached` before committing, and never use `git add -f` for private material. Anything already committed or shared needs separate removal; `.gitignore` cannot undo that.

## Later deployment

After reviewing all public content and running `npm run build`, choose a static host and publish the **contents of `dist/`**. Relative asset URLs support a subdirectory deployment. Configure your host’s build command as `npm run build` and output directory as `dist` if it builds from source. Test the deployed URL, navigation, assets, and links. No deployment has been performed here.
